# MariaDB Stack

## 简介

本 Stack 提供 **MariaDB 数据库服务**，作为 Docker Compose Stacks 项目中
所有数据库相关应用的 **统一数据库能力提供方**。

自 **v1.1.4** 起，MariaDB Stack 在保持既有部署与初始化语义不变的前提下，
完成了 **数据库账号治理模型的受控升级**，为平台级管理、审计与后续应用 Stack
数据库初始化提供了稳定、可继承的语义基线。

---

## 适用范围与版本约束

- 适配项目版本：**v1.1.4 及之后版本**
- 数据库类型：**MariaDB（官方镜像）**
- 不支持：
  - 数据库高可用、主从、集群或代理架构
  - 多数据库类型混合部署
  - 将 root 账号作为远程日常管理账号

---

## Stack 职责边界（重要）

### MariaDB Stack 负责

- 提供数据库运行能力
- 在首次部署时：
  - 自动创建平台级数据库管理员账号
  - 自动创建全库只读审计账号
- 提供稳定、可被继承的数据库初始化语义基线

### MariaDB Stack 不负责

- 不为具体应用创建逻辑数据库
- 不为应用创建专属数据库用户
- 不管理应用级账号生命周期
- 不提供数据库高可用或集群能力

---

## 数据库账号治理模型（v1.1.4 冻结事实）

自 v1.1.4 起，MariaDB Stack 内部的数据库账号角色 **严格区分、职责明确**。

### 1. root 账号（受控）

- 用途：
  - 数据库初始化
  - 紧急维护
- 特点：
  - 不作为远程管理接口
  - 不作为 phpMyAdmin 的推荐或默认登录账号
- 说明：
  - root 权限未被扩展或替代

---

### 2. 平台级数据库管理员账号（推荐）

**示例名称**：`db_admin`

- 用途：
  - phpMyAdmin 管理
  - DBA / 运维管理
- 权限范围：
  - 全库管理权限
  - 与 root 职责严格区分（不等价）
- 连接能力：
  - 允许远程连接

> ✅ 这是平台级数据库管理的**推荐账号**

---

### 3. 全库只读审计账号

**示例名称**：`db_readonly`

- 用途：
  - 查询
  - 审计
- 权限范围：
  - 全库只读（SELECT）
- 限制：
  - 不允许写入、修改或结构性操作
- 连接能力：
  - 允许远程连接

---

## 初始化行为说明（关键）

### 首次部署时的行为

在 **数据目录为空** 的情况下，MariaDB Stack 会在首次启动时：

1. 初始化数据库系统表
2. 根据 `.env` 配置：
   - 创建平台级管理员账号
   - 创建全库只读审计账号
3. 完成权限分配后启动数据库服务

该初始化过程：

- 基于 MariaDB 官方初始化机制
- **仅执行一次**
- 不依赖 Installer 的额外逻辑

---

### 后续启动行为

在以下情况下，初始化脚本 **不会再次执行**：

- 容器重启
- `docker compose restart`
- 宿主机重启
- 删除容器但保留数据目录

仅当 **数据目录被完全删除并重新部署** 时，初始化才会重新发生。

## 配置说明（.env）

### 配置文件位置

首次安装后，配置文件位于运行目录，例如：

```text
/opt/docker/mariadb/.env
```

### 常见配置项说明

- 数据库端口映射
- root 密码（必填）
- 平台级管理员账号用户名与密码
- 全库只读审计账号用户名与密码
- （可选）历史兼容的默认数据库与用户配置

> ⚠️ 所有账号凭据均通过 `.env` 注入，未发生任何硬编码。

---

## 与应用 Stack 的协作方式

在 v1.1.4 中，项目已明确以下初始化语义基线：

- MariaDB Stack：
  - 仅提供数据库能力与平台级账号
- 每一个依赖数据库的应用 Stack：
  - 在自身部署时负责：
    - 创建逻辑数据库
    - 创建专属数据库用户
    - 设置对应密码

该语义作为后续版本应用 Stack 改造的 **统一继承基线**。
